# Danger Classification and Approval supersede auto-execute

Supersedes ADR-0002. That decision ran every Bash tool call immediately with no confirmation, on the grounds that a confirmation step would add UI/state complexity disproportionate to Tib's purpose of making loop mechanics observable, and that manually confirming every call would defeat that same purpose by making the loop tedious to actually drive. This is revisited now because a local model changes the cost side of that trade-off: Tib embeds a Qwen3-1.7B GGUF model (run in-process via mistral.rs) that classifies each pending Tool Call as `safe` or `dangerous` before it runs; only a `dangerous` verdict pauses the loop at Awaiting Approval for a real y/n prompt, so most calls still run with zero manual friction, and the loop stays observable rather than gated. The Local Model is the sole judge — no hardcoded dangerous-command pattern list backs it up or overrides it, a deliberate simplicity choice consistent with Tib's one-tool scope, accepting that a small quantized model's judgment on any specific command isn't perfectly reliable in either direction. Anything that isn't a clear `safe` — a `dangerous` verdict, a response Danger Classification can't parse, or no Local Model available at all (Degraded Mode, e.g. its startup self-test failed) — fails closed to the same Approval prompt, so the new safety net can only ever add friction, never silently skip it.
