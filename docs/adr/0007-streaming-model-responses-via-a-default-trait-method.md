# Streaming model responses via a default trait method

Supersedes ADR-0003. That decision deferred streaming because interleaving partial-response events with ratatui's redraw loop and keyboard-input polling looked like real architectural complexity for a project prioritizing a simple, legible loop. Revisiting it found that most of that complexity was actually in `openrouter-rs` already: `client.chat().stream_tool_aware(...)` yields a `StreamEvent::ContentDelta` per text fragment and assembles tool calls into a complete `StreamEvent::Done` internally, so Tib never has to parse partial tool-call JSON — text-only streaming (ADR-scale judgment call, not a technical limitation) covers the actual visible payoff. The remaining plumbing question was how far streaming should reach into the existing `ModelClient`/`Session` seam. `ModelClient::complete_streaming` was added as a *default* trait method — implementers that don't override it (including `FakeModelClient` in tests) get it for free by calling `complete` once and reporting the whole text as a single delta — so `OpenRouterClient` is the only implementation that needed real streaming logic, and every existing test kept working with a one-line change (an added no-op `on_delta` argument) rather than a rewrite. Chunks reach the Controller as a new `AppEvent::StreamChunk` over an unbounded channel (replacing the previous bounded `mpsc::channel(100)`, so the callback's `send` is a plain sync call with no backpressure to reason about); the streamed text lives only as ephemeral Controller state until the turn completes and the real message lands in `Session`, so `Session`'s own shape and its "no knowledge of the terminal or the channel" boundary are unchanged.
