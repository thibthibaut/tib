# `max_steps` resets per user message, not once per session

`max_steps` caps how many steps (`Session::step_count`) run in response to a single user message, and resets to zero at the start of every `send_user_message` call. Issue #1's spec literally says "maximum number of steps **per conversation**," and `CONTEXT.md` maps "conversation" onto `Session` (the whole app run), which read as a whole-session, never-resetting budget — the first implementation followed that literal wording. That turned out not to be the intent: a whole-session budget means one long exchange can permanently exhaust the app's ability to respond to anything else, for the lifetime of the process, which fails the actual goal ("a hard guarantee the loop can never run away indefinitely") far more harshly than intended and isn't how comparable agent loops budget steps. Resetting per message keeps the guarantee scoped to what it's actually protecting against — one message's tool-calling loop running away — without a wording-literal reading turning a safety backstop into a session-ending trap.
